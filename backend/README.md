Every source's connector lives here, and so does every rule about what a sync may change. The
frontend and the MCP server both talk to this process over REST; the Windows agent dials in over a
WebSocket and never the other way round. Under the default `cronsole.ps1` stack it runs as a host
Node process on `:3000`, not a container.

## 📂 What's in here

| Path | What it holds |
|:---|:---|
| **`src/connectors/`** | One `PlatformConnector` per source. No platform-specific logic is allowed outside this folder. |
| **`src/routes/`** | The REST API. Cross-task routes live under `/api/tools`, not `/api/tasks`. |
| **`src/services/`** | Sync, health, the native scheduler, diagnostics, run history and the rest of the shared logic. |
| **`src/ws/`** | The agent channel: the handshake and per-session HMAC signing of every command. |
| **`src/catalog/`** | The bundled template catalog (`bundled.ts`, `packs.ts`) and the generator for `registry/`. |
| **`src/tools/connect-pack/`** | The agent connect pack, generated by `npm run connectpack:build`. Edit the generator, not the output. |
| **`src/auth/`, `src/middleware/`, `src/config/`** | Token checks (one door for REST and the socket), CORS origins and config parsing. |
| **`prisma/`** | The schema and every migration. |
| **`tests/integration/`** | Tests against a real Postgres. Unit tests sit next to the code in `__tests__/`. |

## ⚡ Commands

```bash
npm install                 # also runs prisma generate
npm run dev                 # applies migrations, then watches src/
npm test                    # unit tests
npm run test:integration    # needs a running Postgres
npm run registry:build      # rebuild registry/ after editing the catalog
```

> [!WARNING]
> An unapplied migration makes a whole feature answer *"Internal server error"* on every route
> while the code, the client and the tests all look correct. `predev` and `prestart` apply them;
> `node scripts/check-migrations-applied.mjs` from the repo root tells you if one is missing.
